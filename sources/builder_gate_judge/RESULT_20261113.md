# builder_gate judge 基准报告（2026-11-13）

## 结论
- 判定通道从 auto 路由（主模型 glm-5.3，云端+思考）切到本地 Ollama
  `qwen3.5:4b-mlx-judge`（config.yaml `auxiliary.判定助手回复末段是否提案式收尾`，
  extra_body `reasoning_effort: none` + `temperature: 0`）。
- 判据 `_JUDGE_SYSTEM` 补「暗示等用户开口」形态例示（plugins/builder_gate/__init__.py）。
- 最终：准确率 21/22（95.5%，漏判仅 W3 条件依附新变体），热态延迟 p50 1.06s /
  max 1.74s（首判 9.57s 为 Ollama 冷加载，20s 超时覆盖）。切换前主模型链路
  实测 3.05–9.88s/判定。
- d1-3B（SystemOne）通道证伪：判据内嵌对照例前 12/14，补例后 13/18 反而劣化且
  延迟升至 ~1.9s——排除式判据 × SystemOne 保守偏置（skill:local-judge-model-routing
  已录的「判据风格×模型认知风格」结论在此判据上复现），不采纳，llama-server 通道停用。
- gemma3-4b（ggml Q4_K_M，4096ctx 专档口径）淘汰：9/22、p50 3.95s——12 失分中
  8 题答非 JSON（真实链路直接 fail-open）、4 题负例误判为正；判据遵循能力系统性
  弱于 qwen 同档。错误方向与 qwen 互补（qwen 漏的 W3/H1/V1/V3 它全对），但底盘
  不可用。gemma4-26b-a4b（13.6GB Q4_0）按用户令停止下载不测（常驻 14GB 本就不
  符内存约束，天花板参照价值不抵流量）。

## 复现
```bash
# 逐题实测（依赖 Ollama 在线且 config 已含该 auxiliary 条目）
.venv/bin/python3 - <<'EOF'
import json, time
from plugins.builder_gate import _is_analyst_signature
cases = json.load(open('sources/builder_gate_judge/benchmark_cases.json'))['cases']
for c in cases:
    t0 = time.time()
    got = _is_analyst_signature(c['text'])
    print(('PASS' if got == c['expected'] else 'FAIL'), c['id'], f'{time.time()-t0:.2f}s')
EOF
```

## 边界
- W3 型「你说行，我就能…」条件依附措辞 4b 漏判；按 2026-11-13 用户裁定，
  逐变体补例式不可持续，不再加模式，属 4b 语义天花板（与技能库 0.950 历史一致）。
  漏判方向=少一次续跑提示（fail-open），非拦截误伤，风险可接受。
- Ollama 5 分钟闲置卸载后首判 ~10s（keep_alive 冷加载），20s 超时覆盖。
- 其余 judge 消费方 task（yinyang/read_think/finish_guard 等）仍走 auto 主模型，
  未在本轮范围；各自判据风格不同，切换须逐个过基准。
